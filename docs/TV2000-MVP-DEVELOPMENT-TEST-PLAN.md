## 1. 计划结论

TV2000 MVP 的目标不是完成全部媒体格式和高级设置，而是验证并交付唯一不可削减的产品闭环：

```text
插入 U 盘
    ↓
打开应用
    ↓
自动播放上次频道
    ↓
上下键切台
    ↓
切回时从原位置继续
```

MVP 应首先运行在具备标准 D-pad 遥控器和可访问 USB 存储的 Android TV / Google TV 9+ 设备上。

在基准团队配置下，建议使用 8 周完成可安装的 Release Candidate。只有 1 名 Android 工程师时，合理周期为 12～14 周；不得通过删除自动化测试、插拔恢复或真机兼容性验证来压缩周期。

## 2. MVP 功能范围

### 2.1 MVP 必须包含

| ID | 功能 | MVP 验收边界 |
| --- | --- | --- |
| MVP-01 | Android TV 应用入口 | 可从电视应用列表启动；横屏全屏；不要求触屏 |
| MVP-02 | 首次存储授权 | 直接进入系统目录授权；授权后自动继续 |
| MVP-03 | 单 U 盘识别 | 同时只保证一个当前 USB 存储卷 |
| MVP-04 | 目录转频道 | U 盘一级目录自动成为频道 |
| MVP-05 | 视频扫描 | 默认只扫描频道目录的直接文件 |
| MVP-06 | 自然排序 | `1, 2, 10`、`S01E01`、`第01集` 顺序正确 |
| MVP-07 | 启动即播放 | 有内容时不出现首页，自动播放 |
| MVP-08 | 全局启动恢复 | 恢复上次实际播放的频道 |
| MVP-09 | 频道独立历史 | 每频道保存当前文件与播放位置 |
| MVP-10 | 遥控器操作 | 上下切台、左右 seek、右双击下一集、左双击回到开头/上一集、OK 暂停、Back 频道列表/退出 |
| MVP-11 | 频道 Overlay | 显示频道号、名称、节目序号和恢复时间 |
| MVP-12 | 自动下一集 | 播放结束后自动播放自然排序的下一集 |
| MVP-13 | 末集停止/循环 | 默认停止；隐藏设置可切换循环 |
| MVP-14 | SRT 字幕 | 自动加载同名 SRT 外挂字幕 |
| MVP-15 | 异常恢复 | 无 U 盘、当前 U 盘移除、历史文件丢失、文件播放失败 |
| MVP-16 | 本地持久化 | Room 保存索引和历史；DataStore 保存基础设置 |
| MVP-17 | 离线运行 | 播放与历史功能不依赖账号或网络 |
| MVP-18 | 性能基线 | 缓存命中启动 ≤2 秒，切台 ≤500ms，应用稳态 PSS <150MB |

### 2.2 MVP 媒体支持承诺

MVP 将“应用支持”和“设备解码能力”分开定义。

#### 发布必须通过

- 容器：MP4、MKV；
- 视频：H.264、H.265/HEVC；
- 音频：AAC；AC-3 在设备公开支持时验证；
- 分辨率：1080p 必须；4K 在具备对应硬解的参考设备上必须；
- 字幕：UTF-8 SRT；
- 常见帧率：23.976、24、25、29.97、30、50、59.94、60fps。

#### MVP 尽力支持但不阻塞发布

- WEBM；
- TS / M2TS；
- MOV；
- 容器内字幕；
- 多音轨自动选择；
- HDR10。

#### 完整 v1 再作为发布门槛

- AVI；
- ASS / SSA 完整样式；
- PGS；
- AV1；
- Dolby Vision；
- 高级音轨与字幕偏好恢复；
- 设备特定音频直通。

Media3 的容器解析与视频解码是两个不同层次；视频最终能否播放取决于设备平台解码器。因此 MVP 不得仅根据文件扩展名宣称“完整支持”某种格式。

### 2.3 MVP 隐藏设置

MVP 只实现以下设置：

- 自动下一集：默认开；
- 最后一集循环：默认关；
- 快进秒数：默认 30 秒；
- 快退秒数：默认 10 秒；
- 自动重扫：默认开；
- 关于：版本号和构建号。

入口使用：

- 3 秒内连续按 `Menu` 5 次；
- 无 `Menu` 键时，在无 U 盘页面长按 `OK` 5 秒。

### 2.4 MVP 明确不包含

- 多 U 盘合并频道；
- 数字键直达频道；
- 用户调整频道顺序；
- 扫描深度设置；
- 单集选择；
- 海报、缩略图或详情页；
- SMB、NFS、WebDAV、Jellyfin、Emby；
- 用户账号、云同步；
- 自动更新；
- 观看统计上传；
- 手机和平板 UI；
- Apple TV、Fire TV、Tizen、webOS 原生版本。

这些功能不得混入 MVP 主路径；如需提前研究，应使用独立技术实验分支。

### 2.5 MVP 完成定义

只有同时满足以下条件，MVP 才能称为完成：

1. MVP-01 至 MVP-18 全部通过；
2. 三类参考真机全部完成核心回归；
3. 24 小时连续播放通过；
4. 500 次自动切台通过；
5. 100 次逻辑插拔测试和至少 30 次人工物理插拔通过；
6. 无 P0/P1 缺陷；
7. 崩溃、ANR、音频重叠和历史损坏均为 0；
8. 安装包可通过遥控器完成从启动到退出的全部操作；
9. 用户在任何普通流程中都看不到文件选择界面。

## 3. 运行设备

### 3.1 正式支持条件

MVP 正式支持满足全部条件的设备：

- Android TV 或 Google TV；
- Android 9 / API 28 或更高；
- 系统声明 `android.software.leanback`；
- 具有 D-pad、OK、Back、Home 的遥控器；
- 至少 2GB RAM；
- 至少 300MB 可用内部存储空间；
- 设备具有 USB-A 接口，或能通过带供电 USB Hub 连接 U 盘；
- Android 系统能够以可移除存储或 SAF 文档树方式暴露 U 盘；
- 硬件至少支持 H.264 1080p 解码；
- 电视系统允许安装第三方 Android TV APK。

推荐但不强制：

- 64 位 ARM；
- USB 3.0；
- 4K H.265 硬件解码；
- 3GB 或更多 RAM；
- exFAT 文件系统支持。

### 3.2 不承诺支持

以下设备即使能够安装 APK，也不在 MVP 正式兼容范围：

- Android 手机和平板；
- 不带标准 D-pad 的触屏设备；
- 仅使用手机投屏的 Chromecast 型设备；
- Apple TV；
- Samsung Tizen TV；
- LG webOS TV；
- Amazon Fire TV；
- 未通过 Android TV / Google TV 认证的通用安卓盒子；
- 厂商禁止第三方 APK 或不向应用暴露 USB 文件的电视；
- Android 8.1 及更早版本。

Fire TV 和通用安卓盒子可以在后续兼容性计划中单独适配，但不能仅因为“基于 Android”就纳入支持承诺。

### 3.3 参考真机矩阵

| 层级 | 建议设备 | 用途 | MVP 要求 |
| --- | --- | --- | --- |
| D1 低配基线 | Xiaomi TV Box S（2nd Gen） | 2GB RAM、USB 2.0、Google TV；验证低内存、慢 USB 和 4K 基础播放 | 必测 |
| D2 高配基线 | NVIDIA SHIELD TV Pro | 3GB RAM、双 USB 3.0、Android TV；验证快速扫描、复杂容器和 4K/HDR 上限 | 必测 |
| D3 电视整机 | 一台 Sony BRAVIA Android TV / Google TV，Android 9+ 且带 USB | 验证电视厂商固件、遥控器、休眠、USB 供电和 Overscan | 必测 |
| D4 最低 API | Android TV 官方模拟器 API 28 | 单元外的 UI、Room migration、按键和生命周期自动化 | 必测 |
| D5 当前 API | Android TV 官方模拟器，项目 target API 对应系统镜像 | 新系统权限、SAF、前后台行为 | 必测 |
| D6 OEM 观察组 | 一台常见 Amlogic 通用安卓盒子 | 发现非标准挂载路径和遥控器 KeyEvent 问题 | 选测，不纳入承诺 |

采购优先级：D1、D3、D2。若预算只能先购买两台，应选择 D1 和 D3；模拟器不能替代电视整机。

设备依据：

- Xiaomi 官方规格显示 TV Box S 二代为 Google TV、2GB RAM、8GB ROM、一个 USB 2.0 接口，并支持最高 4K 60fps；
- NVIDIA 官方规格显示 SHIELD TV Pro 为 Android TV 11、3GB RAM、两个 USB 3.0 Type-A 接口；
- Sony 官方资料表明 Android TV / Google TV 电视可以从 USB 播放内容，但文件系统、端口速率和实际媒体能力依型号而异；
- Android 官方明确建议媒体应用尽可能在物理设备上测试，模拟器不应用于代替全部硬件媒体验证。

### 3.4 U 盘与文件系统矩阵

| 类型 | 容量 | 文件系统 | 用途 | 要求 |
| --- | ---: | --- | --- | --- |
| U1 | 32GB | FAT32 | 最常见兼容路径、4GB 单文件边界 | 必测 |
| U2 | 128GB | exFAT | 大于 4GB 视频、中文路径 | 必测 |
| U3 | 256GB | NTFS | 厂商差异验证 | 选测；取决于系统挂载能力 |
| U4 | 32GB | FAT32 | 1000 个短视频扫描集 | 必测 |
| U5 | 128GB | exFAT | 损坏文件、零字节、长文件名、字幕组合 | 必测 |
| U6 | HDD/SSD | exFAT | 供电不足、慢挂载和休眠恢复 | v1 前必测 |

TV2000 不负责挂载系统本身不支持的文件系统。FAT32 单文件约 4GB 的限制属于文件系统限制；测试 4K 长视频时应使用 exFAT 或设备明确支持的 NTFS。

## 4. 团队与分工

### 4.1 基准人员

| 角色 | 投入 | 主要责任 |
| --- | ---: | --- |
| Android A | 100% | Media3、PlaybackCoordinator、遥控器、Overlay |
| Android B | 100% | StorageProvider、扫描、Room、DataStore、插拔恢复 |
| QA | 第 2 周起 100% | 用例、媒体语料、自动化、真机、性能与稳定性 |
| 产品/设计 | 20% | 状态文案、频道 Overlay、设置和验收决策 |

两名 Android 工程师的模块边界必须通过 Repository 和事件接口隔离，禁止同时修改同一状态机核心文件而不先完成接口评审。

### 4.2 每日质量规则

- 所有合并请求必须通过编译、单元测试和静态检查；
- 核心状态机变更必须增加测试；
- 每个可演示里程碑必须安装到 D1 或 D3 真机；
- 播放错误不得用吞异常方式处理；
- 所有性能事件从第一周开始埋入本地诊断日志，不能在最后一周临时补测。

## 5. 八周开发计划

### Phase 0：技术验证（第 1 周）

目标：在投入完整架构前消除三项最大风险。

开发任务：

1. 创建 Android TV Kotlin 工程；
2. 配置 `LEANBACK_LAUNCHER`、无触屏要求和横屏 Activity；
3. 在 D1、D2、D3 上验证 SAF `ACTION_OPEN_DOCUMENT_TREE`；
4. 验证授权 URI 在重启和重新插入后的可用性；
5. 使用 Media3 播放媒体基准集；
6. 验证 D-pad、Back、Home、Menu 的实际 KeyEvent；
7. 测量 1000 文件目录枚举耗时；
8. 验证 U 盘移除事件的可靠性。

交付物：

- 可安装 PoC APK；
- 存储访问决策记录；
- 格式/设备兼容矩阵初稿；
- 扫描和首帧性能基线；
- 风险清单。

退出条件：

- 三类真机至少能授权并播放一个 H.264 MP4；
- 能收到或可靠轮询得到 U 盘移除状态；
- 确认 Media3 与存储方案可继续；
- 若任一真机无法通过 SAF 访问 USB，必须先确定 MediaStore 或厂商适配方案，不能直接进入 Phase 1。

### Phase 1：频道索引（第 2 周）

开发任务：

- `StorageProvider`；
- `StorageMonitor`；
- Room schema 和 migration 测试框架；
- 一级目录频道发现；
- 视频扩展名过滤；
- 自然排序；
- 稳定 `channelId` / `episodeId`；
- 原子扫描 generation；
- 无 U 盘和无内容状态。

测试任务：

- 自然排序参数化单元测试；
- 隐藏目录、空目录、零字节、Unicode、长路径测试；
- FAT32 与 exFAT 扫描；
- 1、100、1000 文件扫描基线。

退出条件：

- 同一 U 盘重复扫描结果稳定；
- 扫描取消不破坏上一份索引；
- U 盘重新插入后匹配同一频道历史主键。

### Phase 2：播放闭环（第 3 周）

开发任务：

- `PlayerController`；
- `PlaybackCoordinator`；
- 启动选择规则；
- 每频道 Cursor；
- 5 秒周期保存；
- 自动下一集；
- 末集停止与循环；
- Home、前后台和进程恢复；
- 同名 SRT 自动加载。

测试任务：

- Player fake 驱动的状态机单元测试；
- Room 事务和异常终止测试；
- 前后台 100 次；
- MP4/MKV 与 H.264/H.265 基准媒体回归。

退出条件：

- 冷启动可自动播放；
- 三个频道独立保存与恢复；
- 强制停止进程后误差不超过 6 秒；
- 末集行为无文件选择入口。

### Phase 3：电视交互（第 4 周）

开发任务：

- 上下键切台；
- 左右键 seek；
- OK 暂停/播放；
- 频道 Overlay；
- 频道列表 Overlay；
- Back 二段行为；
- 快速连续切台取消；
- 隐藏设置和无 Menu 键兜底入口；
- Focus 和 Overscan 适配。

测试任务：

- KeyEvent 单元/仪器测试；
- 不同遥控器手工测试；
- 500 次自动切台；
- 快速连按、长按和遥控器断连；
- 焦点遍历与 10-foot UI 检查。

退出条件：

- 仅用 D-pad、OK、Back、Home 完成全部核心流程；
- 快速切台没有音频重叠；
- 普通用户无法误入设置或文件列表。

本周结束交付 **MVP Alpha**。

### Phase 4：异常恢复（第 5 周）

开发任务：

- 当前 U 盘移除；
- 同一 U 盘恢复；
- 历史文件丢失；
- 损坏或不支持文件跳过；
- 播放器错误分类；
- 权限撤销与重新授权；
- 数据库写入失败降级；
- 扫描与切台竞态修复。

测试任务：

- 物理插拔；
- ADB/测试接口模拟卸载事件；
- 播放中删除当前文件；
- 损坏媒体与伪扩展名；
- 权限撤销；
- 低存储空间；
- 进程在事务中止时被杀。

退出条件：

- 所有异常都进入已定义 UI 状态；
- 不崩溃、不死循环、不持续发声；
- 恢复后历史不串频道。

### Phase 5：性能与兼容（第 6 周）

开发任务：

- 启动路径裁剪；
- 缓存索引优先；
- 渐进扫描；
- prepare/seek 取消优化；
- 内存泄漏修复；
- 本地结构化诊断；
- Release 构建混淆和资源优化。

测试任务：

- D1、D2、D3 全量媒体矩阵；
- 30 次冷启动；
- 每设备 100 次切台性能采样；
- 1000 文件扫描；
- 4K H.265；
- 24 小时播放；
- 内存、ANR、温升观察。

退出条件：

- 达到第 2.1 节性能目标；
- 无持续增长的内存曲线；
- 设备差异已记录为支持、降级或不支持。

本周结束交付 **MVP Beta**。

### Phase 6：发布回归（第 7 周）

任务：

- 冻结功能；
- AC 与 MVP 用例全量回归；
- 数据库升级与覆盖安装；
- 卸载/重装；
- 中英文文案检查；
- 许可、版本、签名检查；
- D1、D2、D3 用户场景走查；
- 修复全部 P0/P1 和批准范围内的 P2。

退出条件：

- 无开放 P0/P1；
- P2 有明确处置；
- 全量回归连续两轮通过；
- 候选包签名、版本和迁移路径正确。

### Phase 7：候选发布（第 8 周）

任务：

- 生成 Release Candidate；
- 10～20 个目标家庭小范围试用；
- 收集本地诊断包和操作反馈；
- 只接受崩溃、数据丢失、无法播放、遥控器失效类修复；
- 最终 24 小时稳定性复测；
- 输出已知限制与支持设备说明。

退出条件：

- 发布门槛全部通过；
- 试用用户无需指导即可完成插入、启动和切台；
- 产品负责人、技术负责人、QA 三方签署发布。

## 6. 工作分解与优先级

### P0：产品闭环

- 存储授权与在线检测；
- 目录扫描与自然排序；
- 启动即播；
- 每频道历史；
- D-pad 切台；
- 自动下一集；
- U 盘移除；
- 本地数据库。

任何 P0 未完成，MVP 不可发布。

### P1：可用与可靠

- 频道 Overlay；
- 频道列表；
- SRT；
- 隐藏设置；
- 损坏文件跳过；
- 缓存索引；
- 性能指标；
- 24 小时稳定性。

任何 P1 未完成，MVP 只可内部演示，不可交付家庭试用。

### P2：完整 v1

- 多 U 盘；
- 扫描深度；
- 数字键；
- ASS / SSA；
- 字幕与音轨偏好；
- AVI 兼容策略；
- AV1、HDR、Dolby Vision 设备矩阵；
- 应用更新。

P2 不进入 MVP 关键路径。

## 7. 测试策略

### 7.1 测试层级

| 层级 | 工具/方式 | 重点 | 每次提交 |
| --- | --- | --- | --- |
| 单元测试 | JUnit、Kotlin coroutine test | 自然排序、频道编号、启动选择、状态机、完成判定 | 必跑 |
| 数据层测试 | Room in-memory / instrumentation | 事务、migration、扫描快照、并发写入 | 必跑 |
| 播放器组件测试 | Fake Player + Media3 test utilities | prepare、seek、ENDED、错误、取消 | 必跑 |
| UI 仪器测试 | Compose/UI Automator | D-pad、焦点、Back、Overlay、设置入口 | 合并前必跑 |
| 真机 E2E | D1/D2/D3 | USB、解码、生命周期、遥控器、性能 | 每日冒烟；每周全量 |
| 稳定性测试 | 自动事件脚本 + 人工观察 | 24 小时播放、500 次切台、插拔 | Beta/RC |
| 试用验收 | 目标家庭 | 无说明书可用性 | RC |

### 7.2 必须自动化的逻辑

- 所有自然排序规则；
- 频道 ID 和编号稳定性；
- 上次频道在线/离线启动选择；
- 每频道历史隔离；
- 位置小于 5 秒的归零；
- Episode 完成判定；
- 自动下一集、末集停止、末集循环；
- 当前文件丢失后的替代顺序；
- 快速切台只提交最终目标；
- 扫描 generation 防旧结果覆盖；
- 播放错误每会话重试上限；
- DataStore 默认值与边界值；
- Room 从每个已发布 schema 的 migration。

### 7.3 媒体测试语料

仓库或受控测试存储应维护不含版权风险的短媒体语料：

```text
media-corpus/
├── baseline/
│   ├── h264-aac-1080p.mp4
│   ├── h264-aac-1080p.mkv
│   ├── hevc-aac-1080p.mp4
│   └── hevc-aac-4k.mkv
├── subtitles/
│   ├── episode.mp4
│   ├── episode.srt
│   ├── episode.zh.srt
│   └── malformed.srt
├── sorting/
│   ├── 1.mp4
│   ├── 2.mp4
│   ├── 10.mp4
│   ├── S01E01.mp4
│   └── 第01集.mp4
├── errors/
│   ├── zero-byte.mp4
│   ├── wrong-extension.mp4
│   ├── truncated.mkv
│   └── unsupported-codec.mkv
└── performance/
    └── 1000-short-files/
```

每个媒体文件必须附带：

- 容器；
- 视频与音频 codec；
- profile/level；
- 分辨率与帧率；
- HDR 类型；
- 预期支持设备；
- 预期播放结果；
- 文件 SHA-256。

### 7.4 每日冒烟测试

每个工作日的最新可安装包至少在一台真机完成：

1. 启动并自动播放；
2. 三频道上下切换；
3. seek、暂停、继续；
4. 退出并恢复；
5. 自动下一集；
6. 拔出并插回；
7. 打开频道列表；
8. 打开并退出隐藏设置。

目标时长不超过 15 分钟。

### 7.5 每周回归

每周至少在 D1、D2、D3 各执行：

- 全部 MVP 功能；
- FAT32 和 exFAT；
- 1080p H.264；
- 1080p/4K H.265；
- SRT；
- 冷启动 10 次；
- 连续切台 100 次；
- 前后台 20 次；
- 物理插拔 5 次；
- 权限撤销和重新授权；
- 覆盖安装保留历史。

### 7.6 性能测试方法

#### 启动

- 使用 Release 构建；
- 强制停止应用；
- U 盘已挂载并授权；
- 索引已存在；
- 从 Activity 启动事件到目标视频首帧；
- 每设备 30 次，报告 P50/P95/最大值；
- P95 必须 ≤2 秒。

#### 切台

- 目标频道媒体已索引；
- 从按键事件时间到首帧；
- 每设备至少 100 次；
- 分别记录同 U 盘和跨目录；
- P95 必须 ≤500ms；
- 任意次数不得出现音频重叠。

#### 扫描

- 1、100、1000 个 Episode；
- 冷缓存和热缓存分别测量；
- 从目录枚举开始到 Room 快照提交；
- 报告存储型号、文件系统和 USB 端口；
- 1000 文件目标 <1 秒；未达到时不得阻塞已缓存频道首帧。

#### 内存

- 1080p H.264 连续播放 10 分钟后采样；
- 记录 Java heap、native heap 和 PSS；
- 稳态 PSS 目标 <150MB；
- 24 小时曲线不得持续增长；
- 4K 解码器占用单独记录，不与应用泄漏混淆。

### 7.7 稳定性和破坏性场景

- 扫描中拔出 U 盘；
- prepare 中拔出 U 盘；
- 保存进度时强制停止进程；
- 快速切台期间进入 Home；
- Overlay 显示期间切台；
- 当前文件被删除；
- U 盘只读；
- 存储权限撤销；
- 数据库空间不足；
- 500 个重复 KeyEvent；
- 遥控器断连；
- HDMI 休眠与唤醒；
- 电视断电后重启；
- 视频时长发生变化；
- 同名频道和同名文件；
- 1000 文件中混入损坏媒体。

### 7.8 缺陷等级

| 等级 | 定义 | 示例 | 发布规则 |
| --- | --- | --- | --- |
| P0 | 数据损坏、安全或完全不可用 | 历史库损坏、无法启动、写坏 U 盘 | 立即停止发布 |
| P1 | 核心体验失败 | 无法切台、无法续播、拔盘崩溃、持续有声黑屏 | 必须修复 |
| P2 | 有明确绕行的功能问题 | 特定字幕异常、某型号 Overlay 裁切 | 需产品批准 |
| P3 | 轻微视觉或诊断问题 | 非关键间距、日志描述 | 可进入后续版本 |

## 8. MVP 验收场景

### 场景 A：老人首次使用

1. U 盘包含“戏曲”“电视剧”两个目录；
2. 首次启动只出现一次系统授权；
3. 授权后自动播放频道 1；
4. 不提供任何文件选择；
5. 按 `↓` 进入频道 2；
6. 按 `↑` 回到频道 1 原位置。

结果：无需说明书和键盘即可完成。

### 场景 B：每天继续观看

1. 上次观看“西游记”第 18 集 `23:41`；
2. 电视和应用均已完全退出；
3. 再次启动；
4. 2 秒目标内显示视频；
5. 位置误差不超过 1 秒。

结果：不出现“是否继续播放”。

### 场景 C：误拔 U 盘

1. 播放中拔出当前 U 盘；
2. 声音立即停止；
3. 显示设备移除；
4. 插回同一 U 盘；
5. 自动恢复到最近保存位置。

结果：无崩溃、无历史串台。

### 场景 D：坏文件

1. 频道第一集为损坏文件；
2. 第二集可正常播放；
3. 应用提示后自动尝试第二集；
4. 第一集不无限重试；
5. 错误不会把第一集标记为看完。

### 场景 E：最小遥控器

遥控器只有：

```text
↑ ↓ ← → OK Back Home
```

用户仍可完成播放、切台、seek、暂停、频道列表和退出。设置入口缺少 `Menu` 键不影响核心播放。

## 9. 主要风险与应对

| 风险 | 影响 | 优先应对 |
| --- | --- | --- |
| 不同电视对 USB/SAF 暴露方式不同 | 无法扫描 | 第 1 周三类真机验证；StorageProvider 隔离厂商差异 |
| Media3 容器支持不等于设备 codec 支持 | 同文件不同设备结果不同 | 建立媒体语料和每设备能力矩阵；错误安全跳过 |
| 1000 文件通过 SAF 枚举较慢 | 启动超时 | 缓存索引、先播后扫、元数据延迟读取 |
| 遥控器没有 Menu 键 | 无法进入设置 | 无 U 盘页长按 OK 兜底；核心功能不依赖 Menu |
| USB 2.0 或机械硬盘唤醒慢 | 切台超过 500ms | D1 慢速基线；取消旧 prepare；Overlay 立即响应 |
| OEM 返回非标准 KeyEvent | 切台/Back 异常 | 记录 KeyEvent；映射层适配；D3/D6 验证 |
| U 盘供电不足 | 随机断连 | 测试 HDD/Hub；文档建议带供电 Hub |
| AVI 等旧视频无法由 Media3 解析 | 目标家庭内容不可播 | Phase 0 统计语料；完整 v1 决定扩展解析器或调整承诺 |
| H.265/HDR/Dolby Vision 碎片化 | 兼容宣传风险 | MVP 只承诺已验收能力；按设备能力显示诊断，不做统一承诺 |
| 频繁进度写入 | I/O 与数据库磨损 | 5 秒节流；关键生命周期立即写；事务合并 |

## 10. 发布与后续

### 10.1 MVP 发布包

应交付：

- 签名 APK 或 AAB；
- 版本号和构建号；
- 支持设备与已知限制；
- 媒体兼容矩阵；
- 测试报告；
- 性能报告；
- Room schema；
- 本地诊断导出说明；
- 用户仅需一页的“U 盘目录示例”。

### 10.2 MVP 后首个增量

建议按以下顺序进入完整 v1：

1. 多 U 盘；
2. ASS / SSA 与音轨偏好；
3. 扫描深度；
4. AVI/MOV 的明确兼容策略；
5. AV1/HDR/Dolby Vision 设备矩阵；
6. 数字键直达；
7. 更新渠道。

顺序依据是先扩大实际内容可用性，再增加可选操作能力。
